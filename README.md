# СпортМаркет — маркетплейс спортивных событий

Полноценная платформа для спорта по городам: билеты на спортивные события,
аренда/бронирование площадок и любительские мероприятия. Каталог с картой
Яндекс, личный кабинет, модерация и админ-панель.

## Стек

- **Веб**: Next.js 14 (App Router), React, TypeScript, Tailwind CSS, Яндекс.Карты JS API
- **API**: NestJS, Prisma ORM, PostgreSQL, JWT-аутентификация (access + refresh)
- **Монорепозиторий**: pnpm workspaces (`apps/web`, `apps/api`, `packages/shared`)

## Возможности

- Каталог событий и площадок с фильтрами (город, вид спорта, поиск) и интерактивной картой
- Три формата событий: продажа билетов, бронирование площадки, любительские мероприятия (сбор участников)
- Бронирование площадок по слотам с проверкой пересечений и рабочих часов
- Покупка билетов на события с эмуляцией оплаты (mock-провайдер, легко заменить на ЮKassa/CloudPayments)
- Личный кабинет: бронирования, билеты, свои события, свои площадки, избранное, профиль
- Модерация: новые площадки и события проходят проверку администратором перед публикацией
- Админ-панель: статистика платформы, очередь модерации, список пользователей
- Отзывы и рейтинги площадок/событий, избранное

## Быстрый старт

### Вариант A — GitHub Codespaces

Репозиторий содержит готовый конфиг `.devcontainer/`. На GitHub: кнопка **Code** →
вкладка **Codespaces** → **Create codespace on <ветка>**. При первом запуске
автоматически поставятся зависимости, поднимется Postgres, применятся миграции
и сид — останется только выполнить в двух терминалах:

```bash
pnpm dev:api
pnpm dev:web
```

Порт 3000 откроется превью-окном автоматически; порт 4000 (API) должен быть
виден в том же браузере, где открыт Codespace (вкладка **Ports** внизу).

### Вариант B — локально

#### 1. Установка зависимостей

```bash
pnpm install
```

#### 2. База данных

Через Docker:

```bash
docker compose up -d db
```

Либо локальный PostgreSQL: создайте базу и пользователя, соответствующие `DATABASE_URL`.

#### 3. Переменные окружения

```bash
cp apps/api/.env.example apps/api/.env
cp apps/web/.env.example apps/web/.env.local
```

Чтобы включить интерактивную карту Яндекс, укажите `NEXT_PUBLIC_YANDEX_MAPS_API_KEY`
в `apps/web/.env.local` (ключ можно получить в [кабинете разработчика Яндекса](https://developer.tech.yandex.ru/)).
Без ключа каталог и карточки объектов работают в режиме списка (graceful fallback).

#### 4. Миграции и демо-данные

```bash
pnpm db:migrate
pnpm db:seed
```

Сид создаёт 5 городов, 10 видов спорта, 14 площадок и 17 событий, а также тестовых пользователей:

| Роль        | Email                   | Пароль        |
|-------------|-------------------------|---------------|
| Администратор | admin@sport.market     | password123   |
| Организатор | organizer@sport.market  | password123   |
| Участник    | user@sport.market       | password123   |

#### 5. Запуск

```bash
pnpm dev:api   # http://localhost:4000/api (Swagger: /api/docs)
pnpm dev:web   # http://localhost:3000
```

## Структура репозитория

```
apps/
  api/      # NestJS API: auth, users, cities, sport-types, venues,
             # events, bookings, orders, payments, reviews, favorites, admin
  web/      # Next.js: каталог, карта, детальные страницы, личный кабинет, админка
packages/
  shared/   # общие enum'ы и типы для api/web
```

## Модель данных

Ключевые сущности: `User`, `City`, `SportType`, `Venue`, `Event`, `Booking`,
`Order`, `Ticket`, `Payment`, `Review`, `Favorite`. Полная схема — в
`apps/api/prisma/schema.prisma`.

## Оплата

Платежи реализованы через mock-провайдер (`apps/api/src/payments`), который
эмулирует поведение реального эквайринга: создание платежа со статусом
`PENDING` и подтверждение через `/payments/:id/confirm` (аналог webhook'а).
Для продакшена достаточно заменить `PaymentsService` на интеграцию с реальным
провайдером (ЮKassa, CloudPayments и т.п.), не меняя остальную бизнес-логику.
