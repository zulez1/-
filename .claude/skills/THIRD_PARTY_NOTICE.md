# Сторонние скиллы

Скиллы в этой директории взяты из публичного репозитория
[alirezarezvani/claude-skills](https://github.com/alirezarezvani/claude-skills)
(MIT License, © 2025 Alireza Rezvani — полный текст лицензии см.
`THIRD_PARTY_LICENSE.txt`) и отобраны вручную под задачи проекта
СпортМаркет на пути к продовому запуску.

Перед добавлением каждый скилл был проверен на подозрительные паттерны
(сетевые вызовы на неизвестные хосты, `eval`/`exec`, `os.system`,
`curl | sh`, обфусцированный код) — ничего подобного не найдено, все примеры
`curl`/URL в файлах — это иллюстративные команды внутри генерируемых
раннбуков/референсов, а не код, который выполняется сам по себе.

## Отобранные скиллы и зачем

- **ci-cd-pipeline-builder** — генерация GitHub Actions пайплайна под наш
  стек (pnpm workspaces, Next.js, NestJS, Prisma) вместо ручного написания.
- **env-secrets-manager** — аудит `.env`/секретов на утечки в git,
  готовность к ротации ключей (актуально перед выкладкой в паблик).
- **dependency-auditor** — офлайн-аудит npm-зависимостей на уязвимости и
  лицензионные конфликты перед релизом.
- **database-designer** — анализ Prisma-схемы, помощь с миграциями и
  индексами при росте модели данных.
- **observability-designer** — проектирование мониторинга/алёртов
  (metrics/logs/traces) при подключении Sentry и логирования на проде.
- **skill-security-auditor** — инструмент для проверки любых будущих
  сторонних скиллов перед добавлением в проект.

Сознательно не добавлены (пока преждевременно для текущей стадии проекта):
`migration-architect` (zero-downtime миграции — нужен только когда сервис
уже в проде под нагрузкой), `runbook-generator` (операционные раннбуки —
имеет смысл писать ближе к моменту реального запуска), `secrets-vault-manager`
(HashiCorp Vault — избыточно для нашего масштаба, `env-secrets-manager`
покрывает текущие потребности).
